📁 Proyecto 1: Archivos físicos y Filegroups Creación

Enunciado: Crea la base de datos GradosTitulos con archivo primario, secundario para documentos históricos y log de transacciones. Agrega un Filegroup IdxGroup para índices no agrupados y consulta el espacio disponible por Filegroup.
📜 Script T-SQL (resumen)
-- Creación física distribuida
CREATE DATABASE GradosTitulos
ON PRIMARY (
    NAME = GradosTitulos_Data,
    FILENAME = 'D:\BaseDatos2026\GradosTitulos_data.mdf',
    SIZE = 20MB, MAXSIZE = 20GB, FILEGROWTH = 5MB
),
FILEGROUP DocumentosGroup (
    NAME = GradosTitulos_DocData,
    FILENAME = 'D:\BaseDatos2026\GradosTitulos_docdata.ndf',
    SIZE = 10MB, MAXSIZE = 10GB, FILEGROWTH = 2MB
)
LOG ON (
    NAME = GradosTitulos_Log,
    FILENAME = 'D:\BaseDatos2026\GradosTitulos_log.ldf',
    SIZE = 6MB, MAXSIZE = 2GB, FILEGROWTH = 2MB
);
-- Agregar Filegroup IdxGroup
ALTER DATABASE GradosTitulos ADD FILEGROUP IdxGroup;
ALTER DATABASE GradosTitulos ADD FILE (
    NAME = GradosTitulos_Idx,
    FILENAME = 'D:\BaseDatos2026\GradosTitulos_idx.ndf',
    SIZE = 10MB, MAXSIZE = 5GB, FILEGROWTH = 2MB
) TO FILEGROUP IdxGroup;
-- Consulta de espacio disponible
SELECT df.name AS NombreLogico, df.physical_name AS RutaFisica,
       df.type_desc AS TipoArchivo, ISNULL(fg.name, 'PRIMARY') AS GrupoArchivos,
       CAST(df.size * 8.0 / 1024.0 AS DECIMAL(10,2)) AS Total_MB,
       CAST((df.size - FILEPROPERTY(df.name, 'SpaceUsed')) * 8.0 / 1024.0 AS DECIMAL(10,2)) AS EspacioLibre_MB
FROM sys.database_files df
LEFT JOIN sys.filegroups fg ON df.data_space_id = fg.data_space_id;
🔍 Justificación técnica: La separación en tres Filegroups (PRIMARY, DocumentosGroup, IdxGroup) optimiza el rendimiento de E/S al distribuir datos, documentos e índices en diferentes discos. El crecimiento fijo en MB evita fragmentación física. FILEPROPERTY permite calcular espacio libre sin escanear datos.
✅ Buenas prácticas: Validación previa con IF EXISTS, SINGLE_USER WITH ROLLBACK para recreación limpia, nomenclatura estándar (_data.mdf, _idx.ndf, _log.ldf), consultas con vistas de sistema (sys.database_files, sys.filegroups).

⚙️ Proyecto 2: Configuración y colación Ajustes

Enunciado: Consulta las propiedades de colación actuales. Modifica la colación a Latin1_General_CI_AI para soporte nativo de español (tildes y Ñ). Ajusta el crecimiento del archivo primario a 20 MB fijos. Eleva el nivel de compatibilidad a 150 (SQL Server 2019) y activa PAGE_VERIFY CHECKSUM.
📜 Script T-SQL (resumen)
-- Ver colación actual
SELECT name, collation_name, compatibility_level
FROM sys.databases WHERE name = 'GradosTitulos';

-- Cambiar colación (requiere SINGLE_USER)
ALTER DATABASE GradosTitulos SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
ALTER DATABASE GradosTitulos COLLATE Latin1_General_CI_AI;
ALTER DATABASE GradosTitulos SET MULTI_USER;

-- Ajustar crecimiento a 20MB fijos
ALTER DATABASE GradosTitulos
MODIFY FILE (NAME = GradosTitulos_Data, FILEGROWTH = 20MB);

-- Nivel de compatibilidad 150 (SQL Server 2019)
ALTER DATABASE GradosTitulos SET COMPATIBILITY_LEVEL = 150;

-- Activar PAGE_VERIFY CHECKSUM
ALTER DATABASE GradosTitulos SET PAGE_VERIFY CHECKSUM;
🔍 Justificación técnica: La colación Latin1_General_CI_AI (Case-Insensitive, Accent-Insensitive) trata 'á' y 'a' como equivalentes en búsquedas. El nivel 150 habilita Intelligent Query Processing (Batch Mode, UDF Inlining). CHECKSUM detecta corrupción física en páginas de datos.
✅ Buenas prácticas: Uso de SINGLE_USER para cambios críticos, restauración a MULTI_USER, verificación post-cambio con sys.databases, documentación de versiones SQL Server.

💾 Proyecto 3: Modelos de recuperación y respaldos Backup

Enunciado: Cambia secuencialmente el modelo de recuperación a SIMPLE, BULK_LOGGED y FULL. Ejecuta un backup completo, un backup diferencial y un backup del log de transacciones.
📜 Script T-SQL (resumen)
-- Cambiar modelos
ALTER DATABASE GradosTitulos SET RECOVERY SIMPLE;
ALTER DATABASE GradosTitulos SET RECOVERY BULK_LOGGED;
ALTER DATABASE GradosTitulos SET RECOVERY FULL;

-- Backup completo
BACKUP DATABASE GradosTitulos
TO DISK = 'D:\Backups\GradosTitulos_Full.bak'
WITH NAME = 'GradosTitulos-BackupCompleto', COMPRESSION, INIT, STATS = 10;

-- Backup diferencial
BACKUP DATABASE GradosTitulos
TO DISK = 'D:\Backups\GradosTitulos_Diff.bak'
WITH NAME = 'GradosTitulos-BackupDiferencial', DIFFERENTIAL, COMPRESSION, INIT;

-- Backup del log
BACKUP LOG GradosTitulos
TO DISK = 'D:\Backups\GradosTitulos_Log.trn'
WITH NAME = 'GradosTitulos-BackupLog', COMPRESSION, INIT;
🔍 Justificación técnica: SIMPLE trunca log automáticamente (sin point-in-time). BULK_LOGGED minimiza logging en operaciones masivas. FULL permite restauración hasta un minuto exacto. El backup diferencial captura solo cambios desde el último full, reduciendo tamaño y tiempo.
✅ Buenas prácticas: Compresión de backups (COMPRESSION), inicialización con INIT, estadísticas de progreso (STATS), verificación en msdb.dbo.backupset, monitoreo de log con DBCC SQLPERF(LOGSPACE).

🔐 Proyecto 4: Roles y usuarios Seguridad

Enunciado: Crea logins VendedorQhatu y ConsultaCliente, renombrándolos como OperadorTramite y AuditorSenedu. Asigna db_datawriter y db_datareader. Crea un rol personalizado RolSecretariaAcademica con permisos SELECT en esquemas y INSERT en Tramite.Tramite. Aplica DENY en Tramite.Pago para OperadorTramite.
📜 Script T-SQL (resumen)
-- Crear logins
CREATE LOGIN VendedorQhatu WITH PASSWORD = 'Operador2026!', DEFAULT_DATABASE = GradosTitulos;
CREATE LOGIN ConsultaCliente WITH PASSWORD = 'Auditor2026!', DEFAULT_DATABASE = GradosTitulos;

-- Usuarios renombrados
CREATE USER OperadorTramite FOR LOGIN VendedorQhatu;
CREATE USER AuditorSenedu FOR LOGIN ConsultaCliente;

-- Roles integrados
ALTER ROLE db_datawriter ADD MEMBER OperadorTramite;
ALTER ROLE db_datareader ADD MEMBER AuditorSenedu;

-- Rol personalizado
CREATE ROLE RolSecretariaAcademica;
GRANT SELECT ON SCHEMA::Academico TO RolSecretariaAcademica;
GRANT SELECT ON SCHEMA::Tramite TO RolSecretariaAcademica;
GRANT INSERT ON Tramite.Tramite TO RolSecretariaAcademica;

-- DENY explícito en Pago (prevalece sobre db_datawriter)
DENY SELECT, INSERT, UPDATE, DELETE ON Tramite.Pago TO OperadorTramite;
🔍 Justificación técnica: El renombrado permite nombres institucionales manteniendo logins originales. DENY prevalece sobre GRANT de db_datawriter, garantizando protección de datos financieros. Los permisos a nivel de esquema simplifican administración futura.
✅ Buenas prácticas: Política de contraseñas (CHECK_POLICY = ON), principio de mínimo privilegio, verificación con sys.database_permissions, separación de logins (servidor) vs usuarios (base de datos).

🎯 Proyecto 5: Permisos granulares Columnas y EXECUTE

Enunciado: Concede a CoordinadorFacultad (renombrado de GerenteQhatu) SELECT en Evaluation.V_NotaFinalSustentacion. Revoca UPDATE en Tramite.Pago a AsistenteTramite. Concede a PracticanteSistemas SELECT solo en columnas IdPersona, Nombres, ApellidoPaterno, Correo de Academico.Persona. Concede EXECUTE en Tramite.SP_RegistrarTramite a OperadorTramite.
📜 Script T-SQL (resumen)
-- Permisos específicos
GRANT SELECT ON Evaluation.V_NotaFinalSustentacion TO CoordinadorFacultad;
REVOKE UPDATE ON Tramite.Pago TO AsistenteTramite;

-- Permisos a nivel de columnas (protección de datos sensibles)
GRANT SELECT (IdPersona, Nombres, ApellidoPaterno, Correo) ON Academico.Persona TO PracticanteSistemas;

-- Permiso EXECUTE en procedimiento
GRANT EXECUTE ON Tramite.SP_RegistrarTramite TO OperadorTramite;
🔍 Justificación técnica: Los permisos a nivel de columna ocultan datos sensibles (DNI, teléfono, dirección) cumpliendo normativas de privacidad. EXECUTE permite operaciones sin acceso directo a tablas, encapsulando lógica de negocio y garantizando consistencia.
✅ Buenas prácticas: REVOKE vs DENY (revoco permisos existentes, no bloqueo explícito), encapsulamiento con procedimientos almacenados, verificación con sys.database_permissions.

📊 Proyecto 6: Rendimiento y bloqueos DMVs

Enunciado: Describe indicadores clave del Activity Monitor. Desarrolla consultas con DMVs para rastrear bloqueos en tiempo real. Identifica las 5 consultas con mayor consumo de CPU. Verifica el uso real de índices no agrupados y detecta índices sin uso.
📜 Script T-SQL (resumen)
-- Bloqueos en tiempo real
SELECT session_id, blocking_session_id, wait_type, wait_time, wait_resource
FROM sys.dm_exec_requests
WHERE blocking_session_id > 0;

-- Top 5 consultas por CPU
SELECT TOP 5
    qs.total_worker_time / 1000000 AS CPU_Segundos,
    qs.execution_count AS Ejecuciones,
    SUBSTRING(st.text, (qs.statement_start_offset/2)+1,
        ((CASE qs.statement_end_offset WHEN -1 THEN DATALENGTH(st.text)
         ELSE qs.statement_end_offset END - qs.statement_start_offset)/2)+1) AS Consulta
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
WHERE DB_NAME(st.dbid) = 'GradosTitulos'
ORDER BY qs.total_worker_time DESC;

-- Índices sin uso
SELECT OBJECT_NAME(s.object_id) AS Tabla, i.name AS Indice,
       s.user_seeks, s.user_scans, s.user_updates,
       CASE WHEN (s.user_seeks + s.user_scans + s.user_lookups) = 0
            THEN '❌ SIN USO' ELSE '✅ UTILIZADO' END AS Estado
FROM sys.dm_db_index_usage_stats s
INNER JOIN sys.indexes i ON s.object_id = i.object_id AND s.index_id = i.index_id
WHERE i.type_desc = 'NONCLUSTERED';
🔍 Justificación técnica: sys.dm_exec_requests muestra bloqueos activos. sys.dm_exec_query_stats almacena estadísticas de consultas en caché. sys.dm_db_index_usage_stats registra operaciones de búsqueda, escaneo y actualizaciones por índice.
✅ Buenas prácticas: Filtrado de procesos del sistema (session_id > 50), exclusión de esperas inofensivas, uso de CROSS APPLY para obtener texto y plan de ejecución, recomendaciones automáticas basadas en ratios de uso.

🤖 Proyecto 7: Automatización (Jobs) SQL Agent

Enunciado: Diseña scripts para automatizar tareas con SQL Server Agent: backup diario completo, limpieza semanal de auditoría (>15 días y resueltos). Configura el operador DBA_Alertas con notificaciones por email. Crea un job para reconstrucción de índices con fragmentación >30%.
📜 Script T-SQL (resumen)
-- Crear operador DBA_Alertas
EXEC msdb.dbo.sp_add_operator
    @name = N'DBA_Alertas',
    @email_address = N'dba@universidad.edu';

-- Job: Backup Diario (23:00)
EXEC msdb.dbo.sp_add_job @job_name = N'BackupDiario_GradosTitulos';
EXEC msdb.dbo.sp_add_jobstep @job_name = N'BackupDiario_GradosTitulos',
    @step_name = N'EjecutarBackup',
    @command = N'EXEC GradosTitulos.dbo.SP_BackupDiario_GradosTitulos;';
EXEC msdb.dbo.sp_add_jobschedule @job_name = N'BackupDiario_GradosTitulos',
    @name = N'Diario_2300', @freq_type = 4, @active_start_time = 230000;
EXEC msdb.dbo.sp_update_job @job_name = N'BackupDiario_GradosTitulos',
    @notify_level_email = 2, @notify_email_operator_name = N'DBA_Alertas';

-- Job: Reconstrucción de índices (sábado 02:00)
-- Similar con @freq_interval = 64 (sábado), @active_start_time = 020000
🔍 Justificación técnica: Los Jobs programan tareas rutinarias sin intervención manual. Database Mail envía notificaciones en fallos. ALTER INDEX REBUILD WITH ONLINE = ON reconstruye índices sin bloqueos. El umbral del 30% de fragmentación equilibra rendimiento y costo de mantenimiento.
✅ Buenas prácticas: Nombres dinámicos en backups (con fecha/hora), compresión de backups, transaccionalidad en limpieza, reintentos en jobs (retry_attempts), horarios estratégicos (fuera de horario laboral), verificación de existencia con IF NOT EXISTS.

🏗️ Proyecto 8: Reestructuración de tablas ALTER

Enunciado: Agrega la columna PrioridadAtencion (INT) a Tramite.Tramite. Elimina la columna redundante Observaciones. Agrega CHECK CONSTRAINT (Monto > 0) en Tramite.Pago. Modifica NroRecibo de VARCHAR(30) a VARCHAR(60) manteniendo NULL permitido.
📜 Script T-SQL (resumen)
-- Agregar columna con valor por defecto
ALTER TABLE Tramite.Tramite
ADD PrioridadAtencion INT NULL CONSTRAINT DF_Tramite_PrioridadAtencion DEFAULT 3 WITH VALUES;

-- Eliminar columna redundante
ALTER TABLE Tramite.Tramite DROP COLUMN Observaciones;

-- CHECK CONSTRAINT para Monto positivo
ALTER TABLE Tramite.Pago
ADD CONSTRAINT CK_Pago_MontoPositivo CHECK (Monto > 0);

-- Modificar tipo de datos (expansión segura)
ALTER TABLE Tramite.Pago ALTER COLUMN NroRecibo VARCHAR(60) NULL;
🔍 Justificación técnica: WITH VALUES asigna el default a registros existentes. DROP COLUMN es irreversible. CHECK CONSTRAINT impide montos negativos/cero. La expansión de VARCHAR es segura (no hay pérdida de datos).
✅ Buenas prácticas: Verificación de existencia con IF EXISTS/INFORMATION_SCHEMA, uso de DEFAULT con WITH VALUES, pruebas de validación con TRY...CATCH, documentación de cambios.

🕵️ Proyecto 9: Triggers de auditoría Forensic

Enunciado: Crea Academico.AuditoriaPersona y un trigger AFTER DELETE que capture datos eliminados, usuario y fecha. Crea TR_Auditoria_ModificarPago (AFTER UPDATE) que registre valores anteriores/nuevos de Monto. Crea un trigger INSTEAD OF DELETE, UPDATE en Academico.Docente que bloquee operaciones en fines de semana.
📜 Script T-SQL (resumen)
-- Trigger DELETE en Persona
CREATE TRIGGER TR_Auditoria_DeletePersona ON Academico.Persona
AFTER DELETE
AS
BEGIN
    INSERT INTO Academico.AuditoriaPersona (IdPersona, DNI, Nombres, ApellidoPaterno, ...)
    SELECT IdPersona, DNI, Nombres, ApellidoPaterno, ..., SUSER_SNAME(), GETDATE()
    FROM deleted;
END

-- Trigger UPDATE en Pago
CREATE TRIGGER TR_Auditoria_ModificarPago ON Tramite.Pago
AFTER UPDATE
AS
BEGIN
    INSERT INTO Tramite.AuditoriaPago (IdPago, Monto_Anterior, Monto_Nuevo, Usuario)
    SELECT d.IdPago, d.Monto, i.Monto, SUSER_SNAME()
    FROM inserted i INNER JOIN deleted d ON i.IdPago = d.IdPago    WHERE i.Monto != d.Monto;
END

-- Trigger INSTEAD OF para control de horarios
CREATE TRIGGER TR_Seguridad_HorariosDocente ON Academico.Docente
INSTEAD OF DELETE, UPDATE
AS
BEGIN
    IF DATEPART(WEEKDAY, GETDATE()) IN (6, 7)  -- Sábado o Domingo
    BEGIN
        RAISERROR('Operación bloqueada en fin de semana', 16, 1);
        ROLLBACK;
        RETURN;
    END
    -- Ejecutar operación manualmente si es día hábil
END
🔍 Justificación técnica: AFTER DELETE captura datos eliminados usando la tabla lógica deleted. AFTER UPDATE compara inserted y deleted para registrar solo cambios reales. INSTEAD OF intercepta operaciones y permite control granular (ej. horarios).
✅ Buenas prácticas: SET NOCOUNT ON en triggers, captura de metadatos (SUSER_SNAME(), GETDATE(), IP de origen), validación de cambios reales (evita registros innecesarios), RAISERROR con ROLLBACK para seguridad.

🚨 Proyecto 10: Recuperación y DBCC Disaster Recovery

Enunciado: Simula el borrado accidental de Catalogo.EstadoTramite. Restaura la base completa desde backup. Luego, recupera solo los datos de catálogo desde una base auxiliar (GradosTitulos_Auxiliar) usando Cross-Database Queries. Ejecuta DBCC CHECKDB para validar integridad física.
📜 Script T-SQL (resumen)
-- Simular desastre
DELETE FROM Catalogo.EstadoTramite;

-- Restauración completa
ALTER DATABASE GradosTitulos SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
RESTORE DATABASE GradosTitulos FROM DISK = 'D:\Backups\GradosTitulos_Full.bak' WITH REPLACE, STATS = 10;
ALTER DATABASE GradosTitulos SET MULTI_USER;

-- Recuperación parcial (Cross-Database)
INSERT INTO Catalogo.EstadoTramite (Codigo, Nombre, Descripcion, Orden)
SELECT Codigo, Nombre, Descripcion, Orden
FROM GradosTitulos_Auxiliar.Catalogo.EstadoTramite;

-- Verificación de integridad
DBCC CHECKDB('GradosTitulos') WITH NO_INFOMSGS, DATA_PURITY, EXTENDED_LOGICAL_CHECKS;
🔍 Justificación técnica: RESTORE WITH REPLACE sobrescribe la base existente. Cross-Database Queries permiten recuperación selectiva sin perder transacciones del día. DBCC CHECKDB audita integridad física (páginas, índices, integridad lógica). DATA_PURITY valida valores de columnas.
✅ Buenas prácticas: Backup previo al desastre, SINGLE_USER durante restauración, STATS para monitoreo de progreso, verificación de consistencia post-restauración, estrategias múltiples de recuperación (completa y parcial).
