Proyecto 1 · Respaldo Completo Institucional
Enunciado: La Oficina de Tecnologías de Información requiere implementar una política de respaldo completo diario para la base de datos GradosTítulos. El estudiante deberá crear un procedimiento que genere un respaldo completo y registre la fecha de ejecución.
-- =============================================
-- PROYECTO 1: Respaldo Completo Diario
-- =============================================

-- Creación de la tabla de registro de respaldos
CREATE TABLE dbo.RegistroRespaldos (
    id_registro INT IDENTITY(1,1) PRIMARY KEY,
    tipo_respaldo VARCHAR(20) NOT NULL,
    fecha_inicio DATETIME NOT NULL,
    fecha_fin DATETIME NOT NULL,
    tamaño_mb DECIMAL(18,2) NULL,
    ruta_archivo VARCHAR(500) NOT NULL,
    estado VARCHAR(20) NOT NULL,
    mensaje_error VARCHAR(MAX) NULL
);

GO

-- Creación del procedimiento almacenado para respaldo completo
CREATE PROCEDURE dbo.sp_RespaldoCompleto_GradosTitulos
    @ruta_base VARCHAR(500) = 'D:\Backups\GradosTitulos\'
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @fecha_inicio DATETIME = GETDATE();
    DECLARE @fecha_fin DATETIME;
    DECLARE @nombre_archivo VARCHAR(500);
    DECLARE @ruta_completa VARCHAR(600);
    DECLARE @estado VARCHAR(20) = 'EXITOSO';
    DECLARE @mensaje_error VARCHAR(MAX) = NULL;
    DECLARE @tamaño_mb DECIMAL(18,2);

    BEGIN TRY
        -- Validar que la ruta exista, si no crearla
        EXEC xp_create_subdir @ruta_base;

        -- Generar nombre de archivo con timestamp
        SET @nombre_archivo = 'GradosTitulos_FULL_' +
                              FORMAT(GETDATE(), 'yyyyMMdd_HHmmss') + '.bak';
        SET @ruta_completa = @ruta_base + @nombre_archivo;

        -- Ejecutar el respaldo completo
        BACKUP DATABASE GradosTitulos
        TO DISK = @ruta_completa
        WITH
            NAME = 'Respaldo Completo GradosTitulos',
            DESCRIPTION = 'Respaldo completo diario',
            COMPRESSION,
            STATS = 10,
            INIT,
            SKIP,
            CHECKSUM;

        -- Registrar el respaldo exitoso
        INSERT INTO dbo.RegistroRespaldos
            (tipo_respaldo, fecha_inicio, fecha_fin, ruta_archivo, estado)
        VALUES
            ('COMPLETO', @fecha_inicio, GETDATE(), @ruta_completa, @estado);

        PRINT 'Respaldo completado exitosamente: ' + @ruta_completa;

    END TRY
    BEGIN CATCH
        SET @estado = 'ERROR';
        SET @fecha_fin = GETDATE();
        SET @mensaje_error = ERROR_MESSAGE();

        INSERT INTO dbo.RegistroRespaldos
            (tipo_respaldo, fecha_inicio, fecha_fin, ruta_archivo, estado, mensaje_error)
        VALUES
            ('COMPLETO', @fecha_inicio, @fecha_fin, @ruta_completa, @estado, @mensaje_error);

        THROW;
    END CATCH
END;
GO

🔍 Justificación técnica

  • Procedimiento encapsulado: Centraliza la lógica de respaldo para facilitar su ejecución programada.
  • Tabla de registro: Permite auditoría y trazabilidad de todos los respaldos realizados.
  • Timestamp en el nombre: Cada archivo es único e identificable por fecha/hora.
  • CHECKSUM y COMPRESSION: Garantizan integridad y optimizan espacio.
  • Manejo de errores con TRY-CATCH: Captura excepciones y las registra.

✅ Buenas prácticas

  • Separación física: respaldos en unidad diferente (D:\) a la base de datos.
  • Nombres descriptivos: facilitan identificación y mantenimiento.
  • Registro de métricas: tamaño y duración permiten monitoreo de crecimiento.
  • Uso de SET NOCOUNT ON para reducir tráfico de red.
  • Programación automática mediante SQL Agent (job diario).
Proyecto 2 · Backups Diferenciales para Trámites
Enunciado: La universidad necesita reducir los tiempos de respaldo debido al crecimiento de las tablas de los esquemas Tramite y Documento. Diseñe una estrategia que combine respaldos completos semanales y diferenciales diarios.
-- =============================================
-- PROYECTO 2: Respaldo Completo Semanal + Diferencial Diario
-- =============================================

CREATE PROCEDURE dbo.sp_RespaldoDiferencial_GradosTitulos
    @ruta_base VARCHAR(500) = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @fecha_inicio DATETIME = GETDATE();
    DECLARE @nombre_archivo VARCHAR(500);
    DECLARE @ruta_completa VARCHAR(600);
    DECLARE @estado VARCHAR(20) = 'EXITOSO';

    IF @ruta_base IS NULL
    BEGIN
        SELECT @ruta_base = valor
        FROM dbo.ConfiguracionRespaldos
        WHERE parametro = 'RUTA_BASE';
    END

    BEGIN TRY
        EXEC xp_create_subdir @ruta_base;

        SET @nombre_archivo = 'GradosTitulos_DIFF_' +
                              FORMAT(GETDATE(), 'yyyyMMdd_HHmmss') + '.bak';
        SET @ruta_completa = @ruta_base + @nombre_archivo;

        BACKUP DATABASE GradosTitulos
        TO DISK = @ruta_completa
        WITH
            DIFFERENTIAL,
            NAME = 'Respaldo Diferencial GradosTitulos',
            COMPRESSION,
            STATS = 10,
            INIT,
            SKIP,
            CHECKSUM;

        INSERT INTO dbo.RegistroRespaldos
            (tipo_respaldo, fecha_inicio, fecha_fin, ruta_archivo, estado)
        VALUES
            ('DIFERENCIAL', @fecha_inicio, GETDATE(), @ruta_completa, @estado);

    END TRY
    BEGIN CATCH
        -- Manejo de errores similar al proyecto 1
    END CATCH
END;
GO

🔍 Justificación técnica

  • Respaldo diferencial: Captura solo los cambios desde el último completo, reduciendo tamaño y tiempo.
  • Estrategia semanal + diaria: Equilibrio entre tiempo de respaldo y tiempo de recuperación.
  • Configuración centralizada: La tabla de configuración permite cambios sin modificar código.
  • Compresión: Especialmente beneficiosa en respaldos completos (ahorro 70–80%).

✅ Buenas prácticas

  • Parámetros con valores predeterminados para flexibilidad.
  • Centralización de configuración en tablas.
  • Registro detallado de cada operación.
  • Separación de horarios: completos los domingos, diferenciales diarios.

-- PROYECTO 3: Estrategia FULL + DIFF + LOG (24/7)
-- =============================================

-- Configurar modelo de recuperación FULL
ALTER DATABASE GradosTitulos
SET RECOVERY FULL;

    @ruta_logs VARCHAR(500) = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @fecha_inicio DATETIME = GETDATE();

        BACKUP LOG GradosTitulos
        TO DISK = @ruta_completa
        WITH
            NAME = 'Respaldo Log GradosTitulos',

            STATS = 10,
            INIT,
            SKIP,
            CHECKSUM;

        INSERT INTO dbo.RegistroRespaldos
            (tipo_respaldo, fecha_inicio, fecha_fin, ruta_archivo, estado)
        VALUES
            ('LOG_TRANSACCIONES', @fecha_inicio, GETDATE(), @ruta_completa, 'EXITOSO');

    END TRY
    BEGIN CATCH
        -- Manejo de errores
    END CATCH
END;
GO

🔍 Justificación técnica

  • Modelo FULL: Requisito indispensable para respaldos de log y recuperación point-in-time.
  • Log cada 30 minutos: RPO (pérdida máxima de datos) de 30 minutos.
  • Sinergia FULL + DIFF + LOG: Recuperación rápida con FULL+DIFF y granular con logs.
  • Limpieza automática: Elimina logs antiguos según política de retención.

✅ Buenas prácticas

  • Separación física de logs en unidad diferente (L:\).

  • Política de retención automatizada para evitar desbordamiento.
Proyecto 4 · Alta Disponibilidad (RTO 15 min)
Enunciado: Se requiere diseñar una estrategia de recuperación ante desastres con respaldos completos, diferenciales y transaccionales para garantizar una recuperación máxima de 15 minutos.
-- =============================================
-- PROYECTO 4: Estrategia para Alta Disponibilidad (RTO 15 min)
-- =============================================

CREATE PROCEDURE dbo.sp_RecuperacionRapida_GradosTitulos
    @ruta_base VARCHAR(500) = NULL,
    @ruta_logs VARCHAR(500) = NULL,
    @punto_restauracion DATETIME = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @inicio_recuperacion DATETIME = GETDATE();
    DECLARE @archivo_full VARCHAR(500);
    DECLARE @archivo_diff VARCHAR(500);
    DECLARE @archivos_log TABLE (archivo VARCHAR(500), fecha DATETIME);

    IF @ruta_base IS NULL
        SELECT @ruta_base = valor FROM dbo.ConfiguracionRespaldos WHERE parametro = 'RUTA_BASE';

    IF @ruta_logs IS NULL
        SELECT @ruta_logs = valor FROM dbo.ConfiguracionLogs WHERE parametro = 'RUTA_LOGS';

    IF @punto_restauracion IS NULL
        SET @punto_restauracion = GETDATE();

    -- 1. Obtener el último respaldo completo
    SELECT TOP 1 @archivo_full = ruta_archivo
    FROM dbo.RegistroRespaldos
    WHERE tipo_respaldo IN ('COMPLETO', 'COMPLETO_SEMANAL')
    AND estado = 'EXITOSO'
    ORDER BY fecha_inicio DESC;

    -- 2. Obtener el último respaldo diferencial
    SELECT TOP 1 @archivo_diff = ruta_archivo
    FROM dbo.RegistroRespaldos
    WHERE tipo_respaldo = 'DIFERENCIAL'
    AND estado = 'EXITOSO'
    AND fecha_inicio > (SELECT fecha_inicio FROM dbo.RegistroRespaldos WHERE ruta_archivo = @archivo_full)
    ORDER BY fecha_inicio DESC;

    -- 3. Generar script de recuperación
    PRINT 'RESTORE DATABASE GradosTitulos FROM DISK = ''' + @archivo_full + ''' WITH NORECOVERY;';
    IF @archivo_diff IS NOT NULL
        PRINT 'RESTORE DATABASE GradosTitulos FROM DISK = ''' + @archivo_diff + ''' WITH NORECOVERY;';
    PRINT 'RESTORE LOG GradosTitulos FROM DISK = ''' + @ruta_logs + '...'' WITH RECOVERY, STOPAT = ''' + CAST(@punto_restauracion AS VARCHAR) + ''';';
END;
GO

🔍 Justificación técnica

  • RTO 15 minutos: Diseñado con buffers grandes y compresión para acelerar I/O.
  • RPO 15 minutos: Logs cada 15 minutos garantizan pérdida máxima de 15 min.
  • Script dinámico: Genera automáticamente el comando de restauración óptimo.
  • Simulación: Permite probar la estrategia sin impacto.

✅ Buenas prácticas

  • Métricas RTO/RPO claras y medibles.
  • Almacenamiento en discos SSD para minimizar latencia.
  • Monitoreo continuo de tiempos de recuperación.
  • Documentación de la estrategia para operación en crisis.
Proyecto 5 · Estrategia Corporativa Avanzada
Enunciado: Implemente una estrategia avanzada de respaldo que garantice pérdida máxima de información de 15 minutos, incluyendo compresión y verificación automática de integridad.
-- =============================================
-- PROYECTO 5: Estrategia Corporativa Avanzada
-- =============================================

CREATE TABLE dbo.VerificacionIntegridad (
    id_verificacion INT IDENTITY(1,1) PRIMARY KEY,
    archivo_verificado VARCHAR(500) NOT NULL,
    fecha_verificacion DATETIME NOT NULL,
    resultado VARCHAR(20) NOT NULL,
    checksum_calculado VARCHAR(64) NULL,
    detalles VARCHAR(MAX) NULL
);
GO

CREATE PROCEDURE dbo.sp_RespaldoCompletoConVerificacion
    @ruta_base VARCHAR(500) = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @nombre_archivo VARCHAR(500) = 'GradosTitulos_FULL_CORP_' + FORMAT(GETDATE(), 'yyyyMMdd') + '.bak';
    DECLARE @ruta_completa VARCHAR(600) = @ruta_base + @nombre_archivo;

    BEGIN TRY
        -- 1. Respaldo completo con encriptación y compresión
        BACKUP DATABASE GradosTitulos
        TO DISK = @ruta_completa
        WITH
            NAME = 'Respaldo Corporativo Completo',
            COMPRESSION,
            STATS = 5,
            INIT,
            SKIP,
            CHECKSUM,
            COPY_ONLY,
            ENCRYPTION (ALGORITHM = AES_256, SERVER CERTIFICATE = CertBackupEncryption);

        -- 2. Verificación automática de integridad
        RESTORE VERIFYONLY FROM DISK = @ruta_completa
        WITH CHECKSUM;

        -- 3. Registrar verificación
        INSERT INTO dbo.VerificacionIntegridad
            (archivo_verificado, fecha_verificacion, resultado, detalles)
        VALUES
            (@ruta_completa, GETDATE(), 'VERIFICADO', 'Verificación exitosa');

    END TRY
    BEGIN CATCH
        -- Manejo de errores
    END CATCH
END;
GO

🔍 Justificación técnica

  • Verificación con RESTORE VERIFYONLY: Confirma que el archivo es válido y legible.
  • Encriptación AES_256: Protege datos sensibles incluso si los archivos son comprometidos.
  • Compresión nativa: Reduce tamaño 60–80%, ahorrando almacenamiento.
  • COPY_ONLY: No rompe la cadena de respaldos diferenciales.

✅ Buenas prácticas

  • Verificación obligatoria en cada respaldo.
  • Encriptación estándar AES_256.
  • Programación precisa (logs en minutos 0,15,30,45).
  • Monitoreo proactivo con vista de integridad.
Proyecto 6 · Disaster Recovery
Enunciado: Diseñe un esquema de respaldo que permita reconstruir completamente la base de datos en un servidor alterno ante la pérdida total del servidor principal.
-- =============================================
-- PROYECTO 6: Estrategia de Disaster Recovery (DR)
-- =============================================

CREATE TABLE dbo.ConfiguracionDR (
    id_config INT IDENTITY(1,1) PRIMARY KEY,
    servidor_origen VARCHAR(200) NOT NULL,
    servidor_destino VARCHAR(200) NOT NULL,
    ruta_origen VARCHAR(500) NOT NULL,
    ruta_destino VARCHAR(500) NOT NULL,
    frecuencia_minutos INT NOT NULL,
    ultima_sincronizacion DATETIME NULL,
    estado VARCHAR(20) DEFAULT 'ACTIVO'
);

INSERT INTO dbo.ConfiguracionDR
    (servidor_origen, servidor_destino, ruta_origen, ruta_destino, frecuencia_minutos)
VALUES
    ('SRV-GRADOS-PRINCIPAL', 'SRV-GRADOS-DR', 'D:\Backups\GradosTitulos\', 'E:\DR_Backups\GradosTitulos\', 15);
GO

CREATE PROCEDURE dbo.sp_BackupDisasterRecovery
    @modo VARCHAR(20) = 'COMPLETO'
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @ruta_local VARCHAR(500);
    DECLARE @ruta_remota VARCHAR(500);
    DECLARE @nombre_archivo VARCHAR(500);
    DECLARE @comando_robocopy VARCHAR(1000);

    SELECT @ruta_local = ruta_origen, @ruta_remota = ruta_destino
    FROM dbo.ConfiguracionDR WHERE estado = 'ACTIVO';

    -- 1. Realizar respaldo local
    SET @nombre_archivo = 'GradosTitulos_DR_FULL_' + FORMAT(GETDATE(), 'yyyyMMdd_HHmm') + '.bak';
    BACKUP DATABASE GradosTitulos TO DISK = @ruta_local + @nombre_archivo
    WITH COMPRESSION, CHECKSUM;

    -- 2. Replicar al servidor DR con ROBOCOPY
    SET @comando_robocopy = 'ROBOCOPY "' + @ruta_local + '" "' + @ruta_remota + '" "' + @nombre_archivo + '" /COPY:DAT /R:3 /W:10';
    EXEC xp_cmdshell @comando_robocopy;

    UPDATE dbo.ConfiguracionDR SET ultima_sincronizacion = GETDATE() WHERE estado = 'ACTIVO';
END;
GO

🔍 Justificación técnica

  • Replicación automática: Con ROBOCOPY y xp_cmdshell se copian respaldos al servidor alterno.
  • Respaldo independiente: No interfiere con la estrategia regular.
  • Frecuencia 15 min: Sincronización constante para mínima pérdida de datos.
  • Script de restauración automatizado: Genera los comandos para reconstruir en DR.

✅ Buenas prácticas

  • Separación geográfica del servidor DR.
  • Automatización completa de respaldo y replicación.
  • Alertas tempranas para fallos de replicación.
  • Pruebas periódicas de restauración en DR.

Proyecto 1 · Recuperación por Eliminación Accidental
Enunciado: Un administrador eliminó accidentalmente registros relacionados con expedientes de titulación. Restaure la base de datos utilizando el respaldo más reciente.
-- =============================================
-- PROYECTO 1: Recuperación por Eliminación Accidental
-- =============================================

USE master;
GO

-- 1. Identificar el último respaldo disponible
DECLARE @ultimo_respaldo VARCHAR(500);
SELECT TOP 1 @ultimo_respaldo = ruta_archivo
FROM dbo.RegistroRespaldos
WHERE tipo_respaldo IN ('COMPLETO', 'COMPLETO_SEMANAL')
AND estado = 'EXITOSO'
ORDER BY fecha_inicio DESC;

IF @ultimo_respaldo IS NULL
BEGIN
    PRINT 'ERROR: No se encontró respaldo.';
    RETURN;
END

-- 2. Verificar integridad del respaldo
BEGIN TRY
    RESTORE VERIFYONLY FROM DISK = @ultimo_respaldo WITH CHECKSUM;
END TRY
BEGIN CATCH
    PRINT 'ERROR: Respaldo corrupto.';
    RETURN;
END CATCH

-- 3. Forzar desconexión de usuarios
IF EXISTS (SELECT 1 FROM sys.databases WHERE name = 'GradosTitulos')
BEGIN
    DECLARE @kill_cmd VARCHAR(MAX) = '';
    SELECT @kill_cmd = @kill_cmd + 'KILL ' + CAST(session_id AS VARCHAR) + '; '
    FROM sys.dm_exec_sessions
    WHERE database_id = DB_ID('GradosTitulos')
    AND session_id <> @@SPID;
    IF @kill_cmd <> '' EXEC (@kill_cmd);
    ALTER DATABASE GradosTitulos SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
END

-- 4. Restaurar la base de datos
RESTORE DATABASE GradosTitulos
FROM DISK = @ultimo_respaldo
WITH
    MOVE 'GradosTitulos_Data' TO 'D:\Data\GradosTitulos.mdf',
    MOVE 'GradosTitulos_Log' TO 'L:\Logs\GradosTitulos_log.ldf',
    REPLACE,
    STATS = 10,
    CHECKSUM;

ALTER DATABASE GradosTitulos SET MULTI_USER;
PRINT 'Restauración completada exitosamente.';

🔍 Justificación técnica

  • Detección automática del último respaldo: Usa la tabla de registro.
  • RESTORE VERIFYONLY: Valida el archivo antes de restaurar.
  • KILL y SINGLE_USER: Forzan desconexión para restauración sin conflictos.
  • MOVE: Permite reposicionar archivos en las rutas correctas.

✅ Buenas prácticas

  • Validación previa a la restauración.
  • Registro de todas las restauraciones.
  • Manejo robusto de errores con TRY-CATCH.
  • Mensajes informativos durante el proceso.
Proyecto 2 · Restauración en Servidor Alternativo
Enunciado: La universidad requiere habilitar un servidor de contingencia para pruebas y recuperación. Restaure la base de datos GradosTítulos en una nueva instancia SQL Server.
-- =============================================
-- PROYECTO 2: Restauración en Servidor Alternativo
-- =============================================

DECLARE @nombre_db_alternativo VARCHAR(100) = 'GradosTitulos_Contingencia';
DECLARE @ruta_data_alternativa VARCHAR(500) = 'E:\Data\Contingencia\';
DECLARE @ruta_log_alternativa VARCHAR(500) = 'F:\Logs\Contingencia\';

-- Crear directorios de destino
EXEC xp_create_subdir @ruta_data_alternativa;
EXEC xp_create_subdir @ruta_log_alternativa;

-- Obtener estructura de archivos del respaldo
CREATE TABLE #FileList (
    LogicalName NVARCHAR(128),
    PhysicalName NVARCHAR(260),
    Type CHAR(1)
);

INSERT INTO #FileList
EXEC ('RESTORE FILELISTONLY FROM DISK = ''D:\Backups\GradosTitulos\GradosTitulos_FULL_20260628.bak''');

-- Construir comando con MOVE dinámico
DECLARE @comando VARCHAR(MAX) = 'RESTORE DATABASE ' + @nombre_db_alternativo + ' FROM DISK = ''D:\Backups\GradosTitulos\GradosTitulos_FULL_20260628.bak'' WITH ';
DECLARE @logical_name NVARCHAR(128), @tipo CHAR(1);

DECLARE cur CURSOR FOR SELECT LogicalName, Type FROM #FileList;
OPEN cur; FETCH NEXT FROM cur INTO @logical_name, @tipo;
WHILE @@FETCH_STATUS = 0
BEGIN
    IF @tipo = 'D'
        SET @comando = @comando + 'MOVE ''' + @logical_name + ''' TO ''' + @ruta_data_alternativa + @logical_name + '.mdf'', ';
    ELSE IF @tipo = 'L'
        SET @comando = @comando + 'MOVE ''' + @logical_name + ''' TO ''' + @ruta_log_alternativa + @logical_name + '.ldf'', ';
    FETCH NEXT FROM cur INTO @logical_name, @tipo;
END
CLOSE cur; DEALLOCATE cur;

SET @comando = LEFT(@comando, LEN(@comando) - 1) + ', STATS = 10, CHECKSUM, REPLACE;';
EXEC sp_executesql @comando;

PRINT 'Base restaurada como ' + @nombre_db_alternativo;

🔍 Justificación técnica

  • RESTORE FILELISTONLY: Obtiene nombres lógicos para el movimiento.
  • MOVE dinámico: Coloca archivos en rutas del servidor alternativo.
  • Renombramiento: La base se restaura con nombre diferente para evitar conflictos.

✅ Buenas prácticas

  • Separación de archivos en unidades diferentes.
  • Creación previa de directorios.
  • Registro de la operación en tabla de auditoría.
Proyecto 3 · Recuperación por Corrupción del MDF
Enunciado: El archivo principal de datos presenta corrupción física. Implemente el procedimiento de restauración completo utilizando respaldos disponibles.
-- =============================================
-- PROYECTO 3: Recuperación por Corrupción del MDF
-- =============================================

-- 1. Diagnosticar corrupción
DBCC CHECKDB (GradosTitulos) WITH ALL_ERRORMSGS;

-- 2. Identificar respaldos disponibles
DECLARE @archivo_full VARCHAR(500);
DECLARE @archivo_diff VARCHAR(500);

-- Buscar el respaldo completo más reciente
SELECT TOP 1 @archivo_full = 'D:\Backups\GradosTitulos\' + nombre
FROM (
    EXEC xp_cmdshell 'DIR "D:\Backups\GradosTitulos\*.bak" /B /O-D'
) AS backups(nombre)
WHERE nombre IS NOT NULL AND (nombre LIKE '%FULL%' OR nombre LIKE '%COMPLETO%');

-- Buscar respaldo diferencial
SELECT TOP 1 @archivo_diff = 'D:\Backups\GradosTitulos\' + nombre
FROM (
    EXEC xp_cmdshell 'DIR "D:\Backups\GradosTitulos\*DIFF*.bak" /B /O-D'
) AS backups(nombre)
WHERE nombre IS NOT NULL;

-- 3. Restaurar con NORECOVERY (completo + diferencial + logs)
RESTORE DATABASE GradosTitulos FROM DISK = @archivo_full WITH NORECOVERY, REPLACE, CHECKSUM;
IF @archivo_diff IS NOT NULL
    RESTORE DATABASE GradosTitulos FROM DISK = @archivo_diff WITH NORECOVERY, CHECKSUM;

-- Restaurar logs (ejemplo con el último)
RESTORE LOG GradosTitulos FROM DISK = 'D:\Backups\GradosTitulos\Logs\GradosTitulos_LOG_20260628.trn' WITH RECOVERY;

PRINT 'Base recuperada de corrupción.';
DBCC CHECKDB (GradosTitulos);

🔍 Justificación técnica

  • DBCC CHECKDB: Diagnostica la extensión de la corrupción.
  • NORECOVERY: Deja la base en estado de restauración para aplicar más archivos.
  • Secuencia correcta: Completo → Diferencial → Logs.

✅ Buenas prácticas

  • Detección temprana de corrupción.
  • Uso de NORECOVERY para cadena de restauración.
  • Validación post-restauración con DBCC CHECKDB.

Proyecto 1 · Verificación de Integridad de Backups
Enunciado: Verifique que todos los respaldos generados para GradosTítulos sean recuperables.
-- =============================================
-- PROYECTO 1: Verificación de Integridad de Backups
-- =============================================

CREATE PROCEDURE dbo.sp_VerificarIntegridadBackups
    @ruta_base VARCHAR(500) = 'D:\Backups\GradosTitulos\'
AS
BEGIN
    SET NOCOUNT ON;

    CREATE TABLE #ArchivosBackup (
        nombre VARCHAR(500),
        ruta_completa VARCHAR(600),
        tipo VARCHAR(50)
    );

    -- Obtener archivos .bak y .trn
    INSERT INTO #ArchivosBackup (nombre)
    EXEC xp_cmdshell 'DIR "' + @ruta_base + '*.bak" /B /O-D';
    INSERT INTO #ArchivosBackup (nombre)
    EXEC xp_cmdshell 'DIR "' + @ruta_base + 'Logs\*.trn" /B /O-D';
    DELETE FROM #ArchivosBackup WHERE nombre IS NULL OR nombre = '';

    -- Clasificar tipo
    UPDATE #ArchivosBackup
    SET tipo = CASE
        WHEN nombre LIKE '%FULL%' OR nombre LIKE '%COMPLETO%' THEN 'COMPLETO'
        WHEN nombre LIKE '%DIFF%' THEN 'DIFERENCIAL'
        WHEN nombre LIKE '%.trn' THEN 'LOG'
        ELSE 'DESCONOCIDO'
    END;

    UPDATE #ArchivosBackup
    SET ruta_completa = CASE
        WHEN nombre LIKE '%.trn' THEN @ruta_base + 'Logs\' + nombre
        ELSE @ruta_base + nombre
    END;

    -- Verificar cada archivo
    DECLARE @archivo VARCHAR(500), @ruta VARCHAR(600), @tipo VARCHAR(50);
    DECLARE cur CURSOR FOR SELECT nombre, ruta_completa, tipo FROM #ArchivosBackup;
    OPEN cur; FETCH NEXT FROM cur INTO @archivo, @ruta, @tipo;

    WHILE @@FETCH_STATUS = 0
    BEGIN
        BEGIN TRY
            RESTORE VERIFYONLY FROM DISK = @ruta WITH CHECKSUM;
            PRINT '✅ ' + @archivo + ' - VÁLIDO';
            INSERT INTO dbo.VerificacionBackups (archivo_respaldo, tipo_respaldo, fecha_verificacion, resultado)
            VALUES (@ruta, @tipo, GETDATE(), 'EXITOSO');
        END TRY
        BEGIN CATCH
            PRINT '❌ ' + @archivo + ' - CORRUPTO: ' + ERROR_MESSAGE();
            INSERT INTO dbo.VerificacionBackups (archivo_respaldo, tipo_respaldo, fecha_verificacion, resultado, mensaje_error)
            VALUES (@ruta, @tipo, GETDATE(), 'FALLIDO', ERROR_MESSAGE());
        END CATCH
        FETCH NEXT FROM cur INTO @archivo, @ruta, @tipo;
    END

    CLOSE cur; DEALLOCATE cur;
    DROP TABLE #ArchivosBackup;
END;
GO

🔍 Justificación técnica

  • Verificación masiva: Itera sobre todos los archivos .bak y .trn.
  • RESTORE VERIFYONLY: Valida integridad sin restaurar datos.
  • Clasificación automática: Detecta tipo por nombre.
  • Registro histórico: Tabla de verificaciones para auditoría.

✅ Buenas prácticas

  • Verificación programada regularmente.
  • Manejo de errores individual por archivo.
  • Almacenamiento de métricas (tamaño, duración).
  • Vista de monitoreo con indicadores visuales.

-- PROYECTO 1: Respaldo Manual con T-SQL

USE master;
GO

-- Verificar espacio en disco
EXEC xp_fixeddrives;

-- Definir parámetros
DECLARE @ruta_backup VARCHAR(500) = 'D:\Backups\GradosTitulos\';
DECLARE @nombre_archivo VARCHAR(500) = 'GradosTitulos_FULL_' + FORMAT(GETDATE(), 'yyyyMMdd_HHmmss') + '.bak';

BACKUP DATABASE GradosTitulos

WITH
    NAME = 'Respaldo Completo GradosTitulos',
    DESCRIPTION = 'Respaldo manual',
    COMPRESSION,
    STATS = 10,
    INIT,
    SKIP,
    CHECKSUM;

-- Verificar integridad
RESTORE VERIFYONLY FROM DISK = @ruta_completa WITH CHECKSUM;
PRINT 'Respaldo completado: ' + @ruta_completa;

🔍 Justificación técnica

✅ Buenas prácticas

  • Verificación de espacio con xp_fixeddrives.
  • Creación de directorios con xp_create_subdir.
  • Uso de STATS para monitoreo de progreso.

FROM (EXEC xp_cmdshell 'DIR "D:\Backups\GradosTitulos\*.bak" /B /O-D') AS b(nombre)

  • Forzar desconexión si la base existe.
  • Validación post-restauración con DBCC CHECKDB.

Proyecto 1 · Plan de Mantenimiento Semanal
Enunciado: Creación de un Plan de Mantenimiento Semanal.
-- =============================================
-- PROYECTO 1: Plan de Mantenimiento Semanal
-- =============================================

CREATE PROCEDURE dbo.sp_PlanMantenimientoSemanal
    @nombre_base VARCHAR(100) = 'GradosTitulos',
    @modo_prueba BIT = 0
AS
BEGIN
    SET NOCOUNT ON;

    PRINT '=== PLAN DE MANTENIMIENTO SEMANAL ===';
    PRINT 'Base: ' + @nombre_base;

    IF @modo_prueba = 1
        PRINT '⚠️ MODO PRUEBA';

    -- 1. BACKUP COMPLETO
    IF @modo_prueba = 0
    BEGIN
        BACKUP DATABASE @nombre_base
        TO DISK = 'D:\Backups\' + @nombre_base + '_FULL_' + FORMAT(GETDATE(), 'yyyyMMdd') + '.bak'
        WITH COMPRESSION, CHECKSUM;
        PRINT '✅ Backup completado';
    END ELSE
        PRINT '🧪 [PRUEBA] Backup simulado';

    -- 2. REORGANIZACIÓN DE ÍNDICES
    IF @modo_prueba = 0
    BEGIN
        USE @nombre_base;
        EXEC sp_MSforeachtable 'ALTER INDEX ALL ON ? REORGANIZE';
        USE master;
        PRINT '✅ Reorganización completada';
    END ELSE
        PRINT '🧪 [PRUEBA] Reorganización simulada';

    -- 3. ACTUALIZACIÓN DE ESTADÍSTICAS
    IF @modo_prueba = 0
    BEGIN
        USE @nombre_base;
        EXEC sp_updatestats;
        USE master;
        PRINT '✅ Estadísticas actualizadas';
    END ELSE
        PRINT '🧪 [PRUEBA] Estadísticas simuladas';

    -- 4. VERIFICACIÓN DE INTEGRIDAD
    IF @modo_prueba = 0
    BEGIN
        USE @nombre_base;
        DBCC CHECKDB (@nombre_base) WITH NO_INFOMSGS;
        USE master;
        PRINT '✅ Verificación completada';
    END ELSE
        PRINT '🧪 [PRUEBA] Verificación simulada';

    PRINT '=== PLAN COMPLETADO ===';
END;
GO

🔍 Justificación técnica

  • Cuatro etapas: Backup, reorganización, estadísticas, verificación.
  • Modo prueba: Permite validar sin ejecutar acciones destructivas.
  • sp_MSforeachtable: Reorganiza todos los índices de la base.

✅ Buenas prácticas

  • Separación de responsabilidades por etapa.
  • Manejo de errores con TRY-CATCH.
  • Registro de ejecución para auditoría.

CREATE PROCEDURE dbo.sp_AplicarPoliticaRetencion
    @modo VARCHAR(20) = 'LISTAR'  -- LISTAR, ELIMINAR
AS
BEGIN
    SET NOCOUNT ON;

    -- Identificar archivos fuera de política
    SELECT
        ib.nombre_archivo,
        ib.tipo_respaldo,
        ib.fecha_creacion,
        DATEDIFF(DAY, ib.fecha_creacion, GETDATE()) AS Dias_Antiguedad,
        pr.dias_retencion AS Dias_Retencion,
        CASE WHEN DATEDIFF(DAY, ib.fecha_creacion, GETDATE()) > pr.dias_retencion
             THEN 'ELIMINAR' ELSE 'CONSERVAR' END AS Accion
    FROM dbo.InventarioBackups ib
    INNER JOIN dbo.PoliticasRetencion pr
        ON ib.tipo_respaldo = pr.tipo_respaldo
    WHERE ib.estado = 'ACTIVO' AND pr.activo = 1;

    IF @modo = 'ELIMINAR'
    BEGIN
        -- Eliminar archivos físicos y actualizar inventario
        PRINT 'Eliminando archivos fuera de política...';
    END
END;
GO

🔍 Justificación técnica

  • Políticas por tipo: Cada tipo de respaldo tiene retención específica.
  • Modo LISTAR/ELIMINAR: Previsualización antes de eliminar.
  • Cálculo automático: Antigüedad vs. política.

✅ Buenas prácticas

-- =============================================
-- PROYECTO 1: Recuperación antes de eliminación accidental

DECLARE @fecha_objetivo DATETIME = '2026-06-28 10:14:00';

-- 1. Verificar modelo FULL
IF (SELECT recovery_model_desc FROM sys.databases WHERE name = 'GradosTitulos') <> 'FULL'

    ALTER DATABASE GradosTitulos SET RECOVERY FULL;
    PRINT 'Modelo cambiado a FULL.';

RESTORE DATABASE GradosTitulos
FROM DISK = 'D:\Backups\GradosTitulos\GradosTitulos_FULL_20260627.bak'

RESTORE LOG GradosTitulos
FROM DISK = 'D:\Backups\GradosTitulos\Logs\GradosTitulos_LOG_20260628.trn'

✅ Buenas prácticas

Proyecto 3 · Recuperación Selectiva con Base Temporal
Enunciado: Un error afectó las tablas Tramite y Evaluacion. Diseñe una recuperación punto en el tiempo minimizando la indisponibilidad.
-- =============================================
-- PROYECTO 3: Recuperación Selectiva con Base Temporal
-- =============================================

DECLARE @nombre_temp VARCHAR(100) = 'GradosTitulos_Temp_Recovery';
DECLARE @fecha_restauracion DATETIME = '2026-06-28 09:28:00';

-- 1. Restaurar en base temporal
RESTORE DATABASE @nombre_temp
FROM DISK = 'D:\Backups\GradosTitulos\GradosTitulos_FULL_20260627.bak'
WITH
    MOVE 'GradosTitulos_Data' TO 'D:\Data\GradosTitulos_Temp_Recovery.mdf',
    MOVE 'GradosTitulos_Log' TO 'L:\Logs\GradosTitulos_Temp_Recovery_log.ldf',
    NORECOVERY, REPLACE, CHECKSUM;

RESTORE LOG @nombre_temp
FROM DISK = 'D:\Backups\GradosTitulos\Logs\GradosTitulos_LOG_20260628.trn'
WITH RECOVERY, STOPAT = @fecha_restauracion, CHECKSUM;

-- 2. Extraer datos de tablas afectadas
USE @nombre_temp;
SELECT * INTO #Tramite_Backup FROM Tramite;
SELECT * INTO #Evaluacion_Backup FROM Evaluacion;
USE master;

-- 3. Restaurar base principal y reemplazar datos
RESTORE DATABASE GradosTitulos
FROM DISK = 'D:\Backups\GradosTitulos\GradosTitulos_FULL_20260627.bak'
WITH RECOVERY, REPLACE, CHECKSUM;

USE GradosTitulos;
TRUNCATE TABLE Tramite;
INSERT INTO Tramite SELECT * FROM #Tramite_Backup;
TRUNCATE TABLE Evaluacion;
INSERT INTO Evaluacion SELECT * FROM #Evaluacion_Backup;

-- 4. Limpiar
DROP TABLE #Tramite_Backup, #Evaluacion_Backup;
DROP DATABASE @nombre_temp;
PRINT 'Recuperación selectiva completada.';

🔍 Justificación técnica

  • Base temporal: Aísla la recuperación sin afectar producción.
  • Extracción y reemplazo: Solo se restauran las tablas afectadas.
  • Mínima indisponibilidad: La base principal solo se bloquea durante el reemplazo.

✅ Buenas prácticas

  • Aislamiento de operaciones críticas.
  • Limpieza de recursos temporales.
  • Verificación post-recuperación.
